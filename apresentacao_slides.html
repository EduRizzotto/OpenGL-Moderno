1. O que é o OpenGL Moderno e quais problemas resolve?

❌ O Problema: OpenGL Clássico (Modo Imediato)

  • Usado até o OpenGL 2.1 (glBegin, glVertex3f, glEnd).
  • Gargalo CPU → GPU: A CPU enviava vértice por vértice para a placa de vídeo em todo frame (60x por segundo).
  • Redundância de Memória: Um cubo tem apenas 8 cantos, mas precisava enviar 36 vértices (6 faces × 2 triângulos × 3 pontas).
  • Pipeline Fixo: Iluminação e transformações travadas no driver.

✅ A Solução: OpenGL Moderno (3.3+ Core Profile)

  • Dados residentes na VRAM (GPU): A geometria é enviada da CPU para a GPU uma única vez na inicialização.
  • Indexação (EBO): Armazenamos apenas os 8 vértices únicos do cubo e uma lista leve de índices que conectam os triângulos.
  • Pipeline Programável (GLSL): Programamos código que roda direto nos milhares de núcleos da GPU (Shaders).

2. Os 4 Conceitos Fundamentais: VBO, EBO, VAO e GLSL

1. VBO

Vertex Buffer Object

Bloco de memória contínua na GPU (VRAM) que guarda o array bruto de floats dos vértices: Posição $(x,y,z)$, Cor $(r,g,b)$ e Normal $(n_x,n_y,n_z)$.

2. EBO

Element Buffer Object

Buffer na GPU que guarda os índices inteiros indicando quais vértices do VBO formam cada triângulo. Elimina vértices duplicados!

3. VAO

Vertex Array Object

O "gerente de estado": guarda como os bytes do VBO estão organizados (stride e offset) e qual EBO está conectado a ele.

4. GLSL

OpenGL Shading Language

Linguagem baseada em C compilada para a GPU. Divide-se em Vertex Shader (geometria) e Fragment Shader (pixels/luz).

Aplicações, Possibilidades e Limitações

Aplicações: Engines 3D (Godot, motores próprios), CAD/CAM, simuladores físicos, visualização científica (VisPy).
Vantagem: Renderiza milhões de triângulos em tempo real. Limitação: Exige mais código inicial (configurar buffers e matrizes manualmente).

3. Arquitetura e Pipeline: Como a Imagem é Gerada?

1. CPU (Python) Cria arrays NumPy e envia p/ VRAM
➔
2. VAO + VBO + EBO Memória da GPU pronta para leitura
➔
3. Vertex Shader Multiplica matrizes MVP (GLSL)
➔
4. Rasterização Monta triângulos (EBO) e interpola
➔
5. Fragment Shader Calcula cor e luz Phong por pixel
➔
6. Framebuffer Teste Z-Buffer e exibe na tela

O Papel da CPU (Python)

  • Executa uma única vez na carga: glBufferData (envia VBO e EBO).
  • A cada frame: lê entradas do teclado e calcula apenas 3 matrizes $4\times 4$ (Model, View, Projection).
  • Envia essas variáveis leves via glUniform* e dispara 1 única chamada: glDrawElements().

O Papel da GPU (VRAM + GLSL)

  • Armazena toda a geometria pesada na memória de vídeo.
  • Vertex Shader: transforma todos os vértices em paralelo: $v_{\text{clip}} = P \cdot V \cdot M \cdot v_{\text{local}}$.
  • Rasterizador + Fragment Shader: interpola cores/normais baricentricamente e calcula a iluminação de cada pixel.

4. Como o VAO lê o VBO e conecta o EBO na GPU

No nosso código, cada vértice possui 9 números float32 (36 bytes no total = stride):

Atributo 0: Posição (X, Y, Z)
3 floats × 4 bytes = 12 bytes
offset = 0 bytes
Atributo 1: Cor (R, G, B)
3 floats × 4 bytes = 12 bytes
offset = 12 bytes
Atributo 2: Normal (Nx, Ny, Nz)
3 floats × 4 bytes = 12 bytes
offset = 24 bytes

Economia real com o EBO (Exemplo do Cubo)

  • Sem EBO (glDrawArrays): 6 faces × 2 triângulos × 3 vértices = 36 vértices no VBO ($36 \times 36\text{ B} = 1296\text{ bytes}$).
  • Com EBO (glDrawElements): Apenas 8 vértices únicos no VBO ($8 \times 36\text{ B} = 288\text{ bytes}$) + 36 índices inteiros!
  • Em malhas grandes (personagens, terrenos), cada vértice é compartilhado por 6+ triângulos.

Transformações, Câmera e Iluminação

  • Model (u_model): Rotação, Escala e Translação do objeto no mundo.
  • View (u_view): Posição e direção da Câmera (LookAt).
  • Projection (u_projection): Lente perspectiva (FOV, Near, Far).
  • Iluminação Phong no Fragment Shader: Soma das componentes Ambiente + Difusa ($\mathbf{N}\cdot\mathbf{L}$) + Especular ($\mathbf{R}\cdot\mathbf{V}$).

6. Estrutura do Projeto e Dados do VBO / EBO (geometria.py)

Arquitetura Modular em Python

  • geometria.py: Cria os arrays NumPy float32 (VBO) e uint32 (EBO) para 3 malhas: Cubo, Octaedro e Superfície 16×16.
  • transformacoes.py: Implementa as matrizes $4\times 4$ (Rotação, Escala, Translação, LookAt e Perspectiva).
  • shaders/vertex_shader.glsl e fragment_shader.glsl: Programas da GPU.
  • main.py: Cria VAO/VBO/EBO e executa o loop interativo.

Trecho 1: 8 Vértices (VBO) + 36 Índices (EBO)

# 8 vértices únicos: [x, y, z,  r, g, b,  nx, ny, nz]
vertices = np.array([
  [-0.8, -0.8,  0.8,  1.0, 0.2, 0.2, -s, -s,  s], # 0

7. Código Principal: Criando VAO, VBO e EBO (main.py)

Alocação na GPU (criar_vao_vbo_ebo)

vao = glGenVertexArrays(1)
vbo = glGenBuffers(1)
ebo = glGenBuffers(1)

# 1. Ativa o VAO (ele passa a gravar tudo abaixo)
glBindVertexArray(vao)

# 2. Copia os vértices da CPU para o VBO na GPU
glBindBuffer(GL_ARRAY_BUFFER, vbo)
glBufferData(GL_ARRAY_BUFFER, vertices.nbytes,
             vertices, GL_STATIC_DRAW)

# 3. Copia os índices da CPU para o EBO na GPU
glBindBuffer(GL_ELEMENT_ARRAY_BUFFER, ebo)
glBufferData(GL_ELEMENT_ARRAY_BUFFER, indices.nbytes,
             indices, GL_STATIC_DRAW)

Mapeando Atributos e Desenhando

# Stride = 9 floats * 4 bytes = 36 bytes por vértice
stride = 9 * ctypes.sizeof(ctypes.c_float)

# Location 0: Posição (offset 0B)
glVertexAttribPointer(0, 3, GL_FLOAT, GL_FALSE,
                      stride, ctypes.c_void_p(0))
glEnableVertexAttribArray(0)

# Location 1: Cor (offset 12B) | Location 2: Normal (24B)
glVertexAttribPointer(1, 3, GL_FLOAT, GL_FALSE,
                      stride, ctypes.c_void_p(12))
glEnableVertexAttribArray(1)

# No Loop de Renderização (1 comando desenha tudo!):
glBindVertexArray(vao)
glDrawElements(GL_TRIANGLES, qtd_indices,
               GL_UNSIGNED_INT, ctypes.c_void_p(0))

8. Programando a GPU: Vertex e Fragment Shaders (GLSL)

vertex_shader.glsl (Por Vértice)

#version 330 core
layout (location = 0) in vec3 aPos;
layout (location = 1) in vec3 aColor;
layout (location = 2) in vec3 aNormal;

uniform mat4 u_model, u_view, u_projection;
uniform float u_time;
uniform int u_deform;

void main() {
    vec3 pos = aPos;
    // Onda senoidal calculada 100% na GPU!
    if (u_deform == 1) {
        pos.y += sin(pos.x * 3.5 + u_time * 3.0) * 0.25;
    }
    gl_Position = u_projection * u_view * u_model * vec4(pos, 1.0);
}

fragment_shader.glsl (Por Pixel)

#version 330 core
in vec3 vColor, vNormal, vFragPos;
out vec4 FragColor;

void main() {
    // Iluminação de Phong por fragmento:
    vec3 norm = normalize(vNormal);
    vec3 lightDir = normalize(u_light_pos - vFragPos);

    vec3 ambient = u_ambient * vColor;
    float diff = max(dot(norm, lightDir), 0.0);
    vec3 diffuse = diff * vColor;

    // + Componente Especular (brilho)
    FragColor = vec4(ambient + diffuse + specular, 1.0);
}

9. Demonstração Ao Vivo e Conclusões

Parâmetros Modificados Ao Vivo Agora

  • Teclas - e + + W (Wireframe): Construir o Cubo triângulo por triângulo lendo o EBO em tempo real.
  • Tecla M (Modos do Fragment Shader):
    0 = Interpolação do VBO | 1 = Iluminação Phong | 2 = Normais RGB | 3 = Procedural.
  • Tecla 3 + D (Deformação no Vertex Shader): Ondas senoidais na malha 16×16 calculadas na GPU sem atualizar o VBO na CPU.
  • Teclas Z/X e F/V: Alteração das matrizes View (câmera) e Projection (FOV).

Conclusões Finais

  • O conjunto VBO + EBO + VAO elimina o gargalo entre CPU e GPU, mantendo os dados geométricos direto na VRAM.
  • O EBO reduz drasticamente o consumo de memória ao reaproveitar vértices compartilhados entre triângulos.
  • O GLSL transfere a matemática de matrizes ($M, V, P$) e de iluminação para execução massivamente paralela na GPU.
  • Compreender esses 4 pilares é a base de todas as APIs gráficas modernas (OpenGL 3.3+, WebGL, Vulkan e WebGPU).
